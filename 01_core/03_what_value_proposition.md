# WHAT / 提供価値とメカニズムの定義

> **このファイルの位置づけ:** mikkeが「何を提供するか」「なぜそれが機能するか」を定義する軸。
> 機能追加・変更の判断をする際は、ここに定義された価値と整合するかを確認すること。

---

## 1. コアコンセプト

**「今日も見っけた"いいな"を持ち寄る場所」**

- "いいな"は感謝・賞賛に限らない。気づき・感動・嬉しいこと・小さな発見すべてを含む
- 「持ち寄る」＝発信者が主役。受け取る特定の誰かを必要としない
- 「今日も」＝非日常・特別なイベントではなく、日常の延長にある行為

---

## 2. 提供する直接価値

### 2-1. 伝えにくさの軽減（主目的）

| 現状の伝えにくさ（アンケート由来） | mikkeが提供する解決                                              |
| ---------------------------------- | ---------------------------------------------------------------- |
| 習慣がない                         | チャンネルという常設の場を作る                                   |
| 伝える場面がない                   | 日常のSlack上に組み込む                                          |
| 言葉選びが難しい                   | 「誰かへ」でなく「いいなをシェア」に変えて心理的ハードルを下げる |

### 2-2. 副次的価値（主目的を達成した先に生まれるもの）

- **埋もれていた頑張りの可視化:** 日々の小さな努力が組織に見えるようになる
- **部門横断の相互理解:** 「同じ事業部だけどよく知らないあの人」の人となりを知るきっかけ
- **組織らしさの発見（将来仮説・未確定）:** 蓄積されたポジティブな声が「ITSらしい働き方・強み」を浮かび上がらせる → 組織・事業価値の外部発信への転用（`01_why_mvv_origin.md` Section 2 参照）

---

## 3. 機能するメカニズム（なぜこれで変わるか）

### 社会的証明（"赤信号みんなで渡れば"作戦）

```
発信者（タイプA）がオープンに投稿
        ↓
「みんなやってるんだ」が可視化される
        ↓
傍観者の「伝えにくさ」が軽減される
        ↓
発信者が増える → さらに社会的証明が強化される（正のフィードバックループ）
```

**前提条件:** 最初に一定の発信者をオープンな場に引き込めるかどうかが鍵。

---

## 4. Uniposとの差異比較

| 比較軸                 | Unipos               | MIKKE                              |
| ---------------------- | -------------------- | ---------------------------------- |
| 送信先                 | 特定の「誰か」へ     | 不特定（場へのシェア）             |
| ツール                 | 専用ツール（Unipos） | 普段使いSlack                      |
| 投稿内容               | 感謝・賞賛           | "いいな"全般（自分への発見も含む） |
| 閲覧・リアクションのみ | 不明確               | 明示的にOK                         |

---

## 5. mikkeが提供しないもの（スコープ外）

- **評価・査定との連動:** mikkeはパフォーマンス管理ツールではない
- **ネガティブフィードバックの場:** あくまで「ポジティブ」が起点。批判・改善提案の場ではない
- **義務的参加の強制:** 参加しないことを咎めない。「見るだけOK」が原則
