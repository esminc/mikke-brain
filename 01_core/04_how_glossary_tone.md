# HOW / 運用定義・用語集・トーン

> **このファイルの位置づけ:** mikkeを「どう動かすか」の基準を定義する軸。
> 新機能・施策・コミュニケーションを設計する際は、ここの定義に沿っていることを確認すること。

---

## 1. 運用の基本設計

### チャンネル

| 項目             | 定義                              |
| ---------------- | --------------------------------- |
| プラットフォーム | Slack                             |
| チャンネル名     | `#its-mikke`                      |
| 参加方法         | 全員参加（2025年8月より正式運用） |

### 参加ルール（3原則）

1. **見るだけでもOK** — 読むだけで十分。義務はない
2. **リアクションだけでもOK** — 絵文字反応も立派な参加
3. **投稿してもOK** — 日々の"いいな"を自由にシェアする

### 投稿してよい"いいな"の対象

| カテゴリ           | 具体例                                                             |
| ------------------ | ------------------------------------------------------------------ |
| 他チーム・社外の人 | 「〇〇さんの対応が丁寧だった」「取引先のあの姿勢がいいな」         |
| チーム・出来事     | 「今日のミーティングの雰囲気が良かった」「リリースがうまくいった」 |
| 自分自身           | 「今日は丁寧に説明できた」「久しぶりに集中できた」                 |

## 2. 用語集（SSOT）

| 用語                | 定義                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------- |
| **MIKKE（みっけ）** | 「見つけた」の口語。日常の中に"いいな"を発見し、持ち寄る（シェアする）という一連の行為を指す |
| **"いいな"**        | 感謝・賞賛にとどまらず、気づき・感動・小さな嬉しさ・自己肯定を含む広義のポジティブ感情       |
| **伝えにくさ**      | 習慣・場面・言葉などによって、ポジティブを言語化・共有する際に感じる心理的障壁               |
| **オープン**        | チーム内に閉じず、事業部全体で見える状態                                                     |
| **社会的証明**      | 「みんなやってるなら自分もやっていい」と感じる心理メカニズム。mikkeの普及戦略の核            |
| **Unipos**          | 前任の感謝・賞賛シェアツール。mikkeの前提となる比較対象                                      |

## 3. コミュニケーションのトーン定義

### やること（DO）

- **日常語で書く** — 「感謝します」より「ありがとうです！」「いいなって思いました」
- **小さいことを歓迎する** — 「大したことじゃないけど」を肯定する雰囲気を作る
- **自分の感情・視点を起点にする** — 「〇〇さんが良かった（他者評価）」より「〇〇さんの対応に嬉しくなった（自分の感情）」を優先
- **気軽さを伝え続ける** — 施策コミュニケーションでも「ゆるく・気軽に」を繰り返す

### やらないこと（DON'T）

- **義務感・ノルマ感を出す** — 「投稿してください」より「投稿してみてね」
- **評価との接続を示唆する** — 人事評価・査定と無関係であることを明示する
- **特定の人を名指しで褒めることを強制する** — 「誰かへ」の構造を復活させない
- **参加しない人を問題視する** — 「見るだけでもOK」を常に前提に置く
